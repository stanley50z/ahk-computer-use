# Leave desktop state in place and prepare English keyboard input

The Illustrator exploration showed that restoring cursor position and foreground between scripts interferes with hover menus and transient UI. On 2026-10-11 the user replaced that policy: remove per-script restoration, takeover comparison, mouse tracking, and the keep-foreground opt-out, rather than keeping an optional restore mode. This supersedes ADR-0003. Cursor position and focus stay at the last action even on errors and timeouts; scripts still need observable waits and a stable stopping point.

The user reconfirmed that benchmark post-trial cleanup remains separate and unchanged: close owned windows/processes and reload the saved cursor scheme. The watchdog, UI Access, error reporting, and persistent logs also remain.

The same decision requires ACU to select an available English keyboard when input is non-English. Check at startup and immediately before native keyboard sends so later focus changes are covered. Prepare both destination and sending-thread layouts, verify the switch, and preserve native send semantics. Prefer loaded English (United States), then another loaded English layout. If none exists, warn before input; native sends must stop, and a refused switch is also an explicit send failure. Expected startup preparation failures remain warnings so read-only inspection and mouse actions are available. No layout installation, configured-language-list changes, or restoration of the earlier input language.

Microsoft's [WM_INPUTLANGCHANGEREQUEST documentation](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-inputlangchangerequest) specifies a posted request to the focused window and permits the app to reject it. [ActivateKeyboardLayout](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-activatekeyboardlayout) acts on the calling thread/process, so foreign-thread preparation uses the focused control's request while same-thread preparation uses activation directly.
