The subagent controller launched it with a narrowly scoped task: observe Illustrator, press Shift+C once, verify the selected tool, and stop. It was not told the earlier failure result.

Audit added; CUA behavior unchanged

bench/run.py now persists bounded external-file metadata immediately before and after actor capture, including capture failure. bench/runtime_writes.py correlates that metadata with matched Pi or Claude execution records.

  • Coverage: direct regular files in the user's home and shared temp directories. It records file identity, size and nanosecond modification time, not file contents or hashes. It does not recurse through private directories.
  • Automatic overwrite findings require a recognized direct CUA capture request, its matching returned absolute destination in complete successful JSON, and a change to a file that existed before the trial. Relative requests are not resolved against the actor's cwd.
  • A fresh external screenshot is allowed. Other file changes are retained as diagnostic observations rather than blamed on the actor.
  • Old capture JSON printed by a readback command cannot establish a new capture. Unresolved helper scripts, pipelines, missing/truncated output, unsupported event formats and paths outside the bounded roots remain explicitly unverified.
  • The existing conduct/summary path fails a trial for a verified pre-existing screenshot overwrite. Original trials are not regraded. Daemon cwd, screenshot overwrite behavior, prompts, skills and scratch permissions are unchanged.

Important limit: the historical Claude cp.png calls filtered their output. The new audit would retain the pre-existing-file change for review, but without a complete attributable response it would not invent an automatic runtime-overwrite finding. A metadata tuple restored to its old values or a concurrent writer to the same destination can also defeat precise attribution. This is an audit, not prevention or a security sandbox.

Review identified three issues: old capture JSON could be misattributed as a new write; unsupported event formats could claim complete coverage with zero parsed calls; per-trial snapshots did not identify exact per-call write time. Matching direct capture provenance and an audited-call count fix the first two, with red/green regressions. Documentation now states the per-trial timing limit.
