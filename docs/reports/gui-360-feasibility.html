GUI-360 is a usable source of Office tasks for ACU, not a ready-made live benchmark

Feasibility research and test selection · 20 October 2026 · dataset revision 1c46362e · read-only; nothing in bench/ or acu/ was changed

Coverage. GUI-360 covers Word, Excel and PowerPoint on Windows 11 in depth, and nothing else. Its published benchmark is offline: it scores grounding, screen parsing and next-action prediction against recorded screenshots. It ships no live task runner, reset scripts or outcome checkers.

What ACU can use. The task requests and the 135 template documents. A live ACU test opens a template, gives the actor the original request, and checks the resulting document with an independent maintainer checker.

Do not reuse the gold labels as ground truth. In the 29 trajectories I read in full, three tasks marked complete are wrong or contradictory, and about a third lean on Office API shortcuts an ACU actor does not have.

Recommendation. Add excel_4_6298 as the single test. For a subset, add the 8 core tasks in section 5, with 3 easy smoke tasks for integration bring-up. All of them need about 0.5 MB of templates (4.3 MB with the smoke set) and no screenshot archives. Office 16.0.20430 (Click-to-Run) is installed on this machine.

3. Gold-label quality

All 29 inspected trajectories carry complete: yes from GUI-360's LLM judge. These are my readings of their actions against the actual template contents. verified

  • excel_4_6298: the gold types =Sheet1!A2. The source sheet is in, and the gold run had just renamed the new Sheet1 to LinkedData. The formula does not point at the source cell, yet every sub-score says "yes".
  • excel_4_6787: merging A1:H1 across filled header cells. The gold clicks OK on Excel's data-loss warning, and the judge still scores "Data integrity maintained: yes".
  • excel_4s_14999: change $ to €. The gold formats column B, which holds row labels, while the dollar figures sit in C–E. The template's figures are text strings such as $37,706, so number formatting would not change them anyway.
  • word_4_15222: add 3 rows to the existing table. The first gold step is an API insert_table(3,4) that creates a new table, followed by three "Insert Row Below" clicks.
  • API dependence: 9 of the 29 use select_text, select_table_range or insert_table for the hardest selection step. An ACU actor has to do that selection through the GUI, so gold step counts understate the effort.

So I would use GUI-360 for requests and templates, and grade from document state with our own checkers. Comparing ACU's actions with the gold steps would penalize correct alternatives and reward the mistakes above.

4. Best single test proposal

excel_4_6298: link A2 to a new sheet named LinkedData

Request (verbatim): "Link the text from cell A2 in the current sheet to cell A1 in a new sheet named 'LinkedData'."
Template: adult_sexual_behaviors.xlsx (sheet in, A2 = John, active cell H4) · Gold length: 7 steps, all GUI.

Why this one. One short task covers four distinct interactions: adding a sheet, renaming it through the tab context menu or in-place edit, cell navigation, and formula entry. The actor also has to reason about the sheet name, since in is easy to get wrong, and GUI-360's own gold run got it wrong. The outcome is fully deterministic, and the trap discriminates between careful and careless runs. Nothing changes app-level preferences.

Checker. Pass when (1) a sheet named exactly LinkedData exists; (2) LinkedData!A1 holds a formula referring to in!A2 (accept =in!A2, ='in'!A2, =in!$A$2) whose value is John; (3) sheet in is cell-for-cell unchanged. A typed literal John is not a link and fails, as does #REF! or an external-link prompt.

If you want a lower-risk first run for bring-up, use smoke test excel_4_6950 (rename the sheet) to prove the open/check/close plumbing, then switch to this one.

7. How to add them to the bench proposal

  • Assets. Copy the needed templates into bench/assets/gui360/ with a provenance note: dataset revision, source path, SHA-256, and the MIT notice. The core 8 need 6 files (≈ 0.5 MB); the smoke set adds template1.pptx (3.8 MB). Do not download screenshot archives.
  • Scenarios. One file per task under bench/scenarios/gui360-<task-id>.md. Each holds the verbatim request plus the neutral closing line already used by Illustrator v0.11: "Stop when finished, leaving the document open." Nothing GUI-360- or Office-specific goes into acu/.
  • Maintainer prep, outside actor timing. Copy the template to a uniquely named file in the run workspace, open it in its app, maximize the window, and record the window and document identity. GUI-360 tasks assume the document is already open.
  • Checker, outside actor timing. After the actor stops, bind exactly the owned document. Save a copy to grading/ through Office COM (a Word SaveAs2 or Excel SaveCopyAs on a copy, never the user's files), then run the assertions on that copy. This mirrors the Illustrator flow, where the actor isn't asked to save.
  • Cleanup. Close only the owned document without saving. Pre-existing Office documents and windows stay protected, as in the current conduct audit. Opening files also touches Office's recent-files list and AutoRecover; record that in the report.
  • Run order. Get one smoke task passing on one arm, then run the single test on all five arms, then the core 8. Report per-task pass/fail with the checker's evidence. Don't report a GUI-360-comparable score: the setting is live, and theirs is offline.

8. Leakage and validity

  • This report is now part of the tuning record. The 15 IDs above, their requests and their checkers are visible to anyone who reads docs/. Treat them as a development set. For a headline number, draw a sealed holdout with a fixed seed from the same filtered pool of 1,180, excluding these IDs, and keep its checkers out of actor-visible paths.
  • Keep gold data out of the actor's context. Gold thoughts, coordinates, judge reasons and sub-scores reveal the solution path. Nothing from trajectories belongs in acu/ or in prompts; the bench neutrality rule already requires this.
  • Template overlap. Train and test share templates. In a random sample of 45 train headers, 13 of 15 Excel tasks used the same sheet as 91% of Excel test tasks, and every PowerPoint task used a template that also appears in test. The split is by trajectory, not by template.
  • Public exposure. GUI-360 is public, so frontier models may have seen it in pretraining. The tasks are generic Office operations, which limits the advantage, but it is not zero.
  • Checker scope. Each checker defines success more strictly than GUI-360's LLM judge, for example a real link rather than a typed value. Say so in reports instead of calling results GUI-360 scores.
