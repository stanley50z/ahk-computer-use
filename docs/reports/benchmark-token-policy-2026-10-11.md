# Benchmark policy: tokens, code share and computer-use call time

Specification: [issue #18](https://github.com/stanley50z/ahk-computer-use/issues/18).

## Decision

The user replaced end-to-end task-time comparison with:

1. **Total API tokens per task attempt**, including separate input/cache/output fields.
2. **Estimated computer-use code/argument tokens as a percentage of output tokens including reasoning.** The user explicitly chose code/arguments only, not whole-response attribution, and chose output-including-reasoning rather than all API tokens as the denominator.
3. **Computer-use tool-call durations**, excluding model-response latency.

The runtime label is **Codex computer use**. The five configurations, models, scenario prompts/assets, correctness/quality checks, standing authorization and cleanup policy are unchanged. Technical vendor API identifiers and original evidence filenames retain their real spelling; current report labels do not call the runtime "native".

Historical elapsed-time reports and original trial files are unchanged. Their timing figures are historical evidence, not the new ranking criteria. Higher code share or fewer tokens cannot turn a blocked/invalid submission into a successful task.

## What the numerator counts

`bench/efficiency.py` reconstructs attribution from structured arguments captured in the original tool events:

- Direct ACU/CUA execution commands and Codex computer-use JavaScript payloads.
- Generated helper source written with Write or shell heredocs and later used by identified runtime invocations.
- Generated edit text or script-edit commands that contribute to later replay. Old text used merely to locate an edit is not counted as newly generated source.
- Imported Python helpers, literal/aliased subprocess command prefixes, and persistent JavaScript helpers whose bodies reference `sky` or an established computer-use helper.
- Recognized runtime lifecycle calls, including ending a CUA session or resetting the Codex computer-use JavaScript context.

One emitted source payload is counted once, even if its script executes repeatedly. Re-emitting a whole script or a new edit consumes tokens again and counts again when used. Moving or deleting helpers after execution does not erase captured provenance. Script paths/renames are retained, with basename resolution only when unambiguous in the captured history.

Read results, reasoning, standalone prose/final answers, and standalone result-file writes are excluded. The previous false match from `cua-driver` inside a result JSON string no longer counts as computer use. CUA help/version/schema lookups alone are not desktop execution calls.

**Mixed invocation payloads are inclusive.** If one shell command both creates/runs an action script and performs ancillary work, the generated command/code payload is counted as a unit. Source comments are included; this is not an executed-instruction or dead-code analysis. Arbitrary shell/Python/JavaScript semantics cannot be inferred perfectly from text; unsupported or ambiguous forms carry review notes, and a percentage is withheld when those notes make attribution incomplete. Close comparisons require review of the selected payload ledger.

The reference tokenizer is **tiktoken 0.14.0 / o200k_base** for this replay. Its version and encoding are recorded per result. This common encoding is not asserted to be either Astra's or Opus's exact billing tokenizer. Dividing the estimate by provider-recorded output gives a useful approximate share, not an exact allocation of billed tokens.

## What execution time means

Each selected top-level tool call retains:

- call ID and tool name;
- request and result receipt timestamps;
- elapsed call duration;
- tool-reported error indication.

The report provides both **sum of durations** and **busy-time union**. Concurrent spans are charged once in the union. Model-response time, model queueing and the gaps between calls are outside these spans. Missing request timestamps or unfinished calls are incomplete timing, not zero-duration successes; known spans remain available separately.

A shell call may contain script creation, multiple ACU/CUA invocations, sleeps, file inspection or other ancillary work. Its duration includes that work. Therefore the numbers in the table are **computer-use host tool-call busy time**, not pure runtime CPU time, mouse-event latency, or actual CLI-launch counts. The Pi+ACU replay, for example, includes the broad output-file search that it bundled with an ACU screenshot call.

The selected host-call counts are 19 (Pi+ACU), 49 (Pi+CUA), 50/22 (Codex computer-use interrupted/retry), 20 (Claude+ACU), and 42 (Claude+CUA). These differ from the earlier regex-only classifier, especially for moved/imported CUA helpers and evidence strings. They must not be confused with model responses or individual clicks/drags.

## Implementation and validation

- `bench/run.py` now retains structured arguments for Pi, Claude Code and archived Codex CLI events. New run summaries expose `benchmark`; their wall duration is explicitly diagnostic, and they no longer score `task_s`.
- `bench/efficiency.py` produces the versioned token/attribution/duration ledger without reading final workspace script files or executing actor code.
- `bench/intervals.py` supplies shared overlap-safe interval arithmetic.
- `plan.json` records `measurement_policy: tokens-and-computer-use-v1`.
- `analyse` rebuilds the new policy from original events. It prints the new analysis and does not rewrite historical records. The old `--reference-tps` normalization option is removed from the CLI.
- The project dev environment includes the reference tokenizer; use `uv sync`.

Focused regression checks cover generated-script replay, edits, append and both heredoc redirection styles, opening-line execution, imported/moved/renamed helpers, separate same-basename scripts, JavaScript helper reassignment/reset, false runtime mentions in evidence, incomplete API usage, missing tool-start events, and the real CLI reanalysis boundary.

Validation: **74 focused benchmark tests passed; one desktop integration test was intentionally deselected.** All six real Illustrator attempts were then analysed through the public CLI, with original hashes verified unchanged. No desktop was used for this measurement change and no temporary server/port was started.
