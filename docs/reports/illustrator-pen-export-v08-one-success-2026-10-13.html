Did all five succeed on the first try?

Not if you count every launch. Yes if you mean the first actor trial.

That does not mean five flawless playthroughs. Several actors repaired script errors, input delivery, dialogs or drawing mistakes within their own session. Pi CUA also recovered from a provider-response failure.

How the statistics compare

Within Claude Code, CUA consumed 10.77× as many API tokens as ACU. ACU also had better image overlap in this run: 93.29% versus 89.28%. Both drawings passed; neither was an exact reproduction.

All five execution ledgers are now attributed. Offline replay recovered 39 omitted Pi CUA calls and two Claude CUA calls. Their corrected counts are 61 and 38. These are single-sample observations. They do not establish typical performance or reliability. Pi uses GPT-6 Astra; Claude Code uses Opus 5.5. Compare runtimes within the matched harness/model groups rather than treating the five rows as a controlled model comparison.

What this run proves, and what it does not

Fixed task and checks

  • v0.8 is drawing-only. Recreate the reference with the Pen tool, genuine Bézier direction handles and fill #00AEEF, then leave the drawing open.
  • Pi arms use gpt-6-astra at low reasoning; Claude Code arms use claude-opus-5-5 at low effort. Each receives only its assigned computer-use runtime.
  • The controller exports the owned live drawing as-is, after the actor stops. Export, observation and cleanup are outside actor token/call measurements.
  • All five passed drawing, conduct, assigned-runtime session review, maintainer export, owned-resource cleanup and cursor-restoration checks. Recorded worker and actor processes had exited.

Limits and policy

  • One successful sample per configuration, not a multi-trial average. There is no confidence interval or reliable success-rate estimate.
  • Six controller launches do not equal six actor trials: the first Pi ACU launch failed before actor startup. Provider retries and drawing edits inside a session are not new trials.
  • The user explicitly replaced the normal three-scheduled-attempts/no-replacement rule with one success per configuration for this request. Frozen plans still carry the default trial-policy metadata; the request manifest records this override. The three-trial aggregator was not used.
  • No prompt, neutral skill, model, grading threshold or asset was changed to obtain a pass. The infrastructure fix was only interpreter selection.
  • End-to-end task time and provider speed are not ranking metrics. The report uses API consumption, attributed execution spans and drawing quality.
