## What the freedom changed

**Three of four actors kept pressing buttons.** Both ACU actors and the CUA actor chose UI Automation Invoke exactly as before, even though the prompt now offered the keyboard. Their skills steer them to named controls, the controls were right there in the tree, and nothing in the task made typing look cheaper.

**The native actor typed, and it was its best result so far.** It sent the expression as 26 numpad key presses in one REPL cell, then Return, instead of 27 click cells each in its own model turn. That cut its task time from 206 s to 135 s and its tokens from 1.07 million to 419 thousand. The remaining cost is inside the runtime: its skill asks for a state capture after every key, and the one cell with 26 keys ran for 89.3 s, about 3.4 s per key, the same per-action price as a click. Accessibility was null again; it read the expression and result from screenshots.

**ACU's number is where it was.** Pi + ACU ran the same three-response shape as round 3 and landed at 17.5 s. Its calculation script now ends with `AcuWaitUntil` on the expression showing `=`, then the display, then `AcuScreenshot`, all in one run. Claude Code + ACU took longer than in round 3 because it guessed AutomationIds such as `oneButton` instead of reading them, failed on the first digit, dumped the tree, and reran: a self-inflicted detour of two computer-use calls that its own hiccup list reports. The launch-plus-look example in the skill was there; it read the mode header but not the button ids.

**CUA's shape was unchanged**: 27 click-and-refresh pairs in one helper, 49.4 s, and the usual `Minus (` screenshot check.
