# Testbench 1: three-configuration Calculator comparison

**Testbench 1 is the Calculator UI task as a whole, across Pi + ACU, Pi + CUA, and Codex + native computer use.** A single configuration is an arm, not the complete benchmark. This definition is recorded in `CONTEXT.md` and `bench/README.md` by the user's correction.

All three fresh actors used GPT-6.1 (`gpt-6.1-sol`) at low reasoning and completed the same v3 prompt. Pi used the `openai` provider. The runs were sequential, with a 240-second actor limit. No parent coaching, automatic whole-trial retry, provider fallback, or implementation/skill edits occurred during the timed runs. The earlier 75.64-second ACU-only trial is separate evidence and was not reused here.

These historical trials used the then-existing 240-second actor cap. The user subsequently removed the overall benchmark deadline; the recorded runs and timings below are unchanged. See [latency analysis and deadline removal](testbench-1-latency-2026-10-10.md).

Source: `de19715`. All scenario hashes matched:

## Outcome

**All three passed the task, actual-session isolation audit, and recorded cleanup.** The independent observer read each owned Calculator window and captured its displayed result:

```text
128 + 465 × 12387 ÷ 138473 − 12343
= -12,173.403768243628721844691744961
```

Pointer clicks and semantic UI button activation were permitted. No keyboard input, direct field-value injection, clipboard input, or arithmetic outside Calculator was used. The observer's fixed reference and screenshot checks ran outside actor timing.

CUA took about 2.50 times ACU's wall time, and native computer use about 4.41 times. These are one successful sample each, not a statistical ranking. Prompt versions/hashes match in this comparison, but cache/latency conditions, launcher defaults, observation routes, and skill-driven workflows differ.

Native tool intervals and request counts were audited separately from the captured exec events and persisted rollout. Its request count comes from 35 distinct cumulative usage records, not from assuming each tool call equals a model request. Native uncached input is aggregate input minus cached input. Reasoning counts match the final native rollout usage and are already part of output.

Codex exec does not provide authoritative per-response model duration. Its measured turn interval was 223.388 s; subtracting tool busy intervals leaves **121.649 s of estimated model plus orchestration time**, not exact model latency or decoding time. Raw summary metrics remain unchanged; this estimate is supplemental audit data.

Tokens sum API usage across turns, including repeatedly cached context; they are not unique prompt size or final context length. Harness call counts are not numbers of UI button presses: a shell/helper call can contain many operations. Wall time excludes independent verification, lifecycle release, and cleanup.

## What each configuration did

### Pi + ACU

- Made three desktop shell calls, all through the installed `acu run` CLI: launch, accessibility-tree inspection, and one AHK action chain.
- Found a unique new window by observed title/handle, recorded ownership before input, and invoked all 27 number/operator buttons by name.
- Calculator was already in Scientific mode; the script checked that state before calculating.
- Reported the result through the display element. The accessibility expression text contained the unusual `Minus (` wording, which it preserved verbatim rather than silently correcting.
- The parent observer's screenshot independently showed the intended expression. No actor screenshot call was needed for task completion.

### Pi + CUA

- Used only the installed `cua-driver` skill/runtime, client version 0.34.0.
- Its first launch request used the old ended lifecycle label `calc-v3` and was rejected before UI interaction. A new run-specific label, `calc-051744-owned`, succeeded. This was an in-trial lifecycle hiccup, not a parent retry of the benchmark.
- Opened navigation and selected Scientific Calculator through UI buttons, then ran a Python helper that used snapshot-bound element tokens for each click and refreshed state after each action.
- The helper invoked only `cua-driver` operations; it did not replace UI interaction with Python arithmetic or another automation backend.
- The actor left its named CLI lifecycle open. After the timed run and observer cleanup, the parent explicitly ended **only** `calc-051744-owned` and rechecked cursor-scheme restoration. No shared daemon was stopped.

The actor said semantic activation was reliable but the skill was verbose/repetitive, and noted the ended-session rejection. Unlike the other two arms, this arm exercised mode changes, so starting UI state was not identical despite the matching task prompt.

### Codex + native computer use

- Used Codex CLI 0.162.0, the installed computer-use skill build 26.901.51231, and the bundled `@oai/sky` entry point through `node_repl`.
- Read its own skill plus guidance, API, and confirmation references. No other skill or desktop automation route was used.
- Created a new Calculator through `sky.launch_app`, selected a returned unique window, and wrote ownership before input.
- Accessibility was null; it used screenshot-bound pointer clicks, refreshing the screenshot after each of the 27 number/operator inputs.
- Made 32 `node_repl.js` calls and two shell calls that only read the selected skill/reference files. Ownership/result JSON was written through Node's filesystem API, as permitted for evidence.
- Finished roughly 14.52 seconds before the actor limit. It reported that the screenshot-per-click workflow was slow.

No custom native-helper protocol, direct PowerShell UI Automation, manual helper executable, keyboard input, or external arithmetic appeared in the reviewed calls. The rollout stores custom `exec` wrappers; actual native action arguments were audited from the completed exec tool items rather than assuming old `function_call` rollout shapes.

## Cleanup and limits

Each bench worker closed only its claimed new Calculator window after binding/checking native process identity, found no remaining new Calculator windows, stopped its owned process tree, deleted its temporary credential copy, and released the controller lock. All six recorded worker/actor PIDs were independently verified absent:

- ACU: worker 40928, actor 48404, owned window 7673090.
- CUA: worker 50528, actor 55480, owned window 2235194.
- Native: worker 47804, actor 33364, owned window 2300730.

The saved Windows cursor scheme was reloaded and the OS showing flag checked after each trial. CUA's named lifecycle was additionally ended explicitly outside timing. These are recorded cleanup checks, **not pixel-level proof of visible cursor rendering**. The earlier invisible-cursor incident's precise cause remains unproven; no security settings or shared host services were changed.

Original transcripts, action results, and scripts were retained as evidence. No full desktop suite or extra benchmark trial was run. No implementation fixes were made in response to the observed hiccups.
