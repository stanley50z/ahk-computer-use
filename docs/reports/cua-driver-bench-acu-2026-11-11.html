Multi-app tasks: what went wrong

  1. AutoHotkey side doors. An ACU script is a full AutoHotkey program, so it can read files, start processes and rewrite data that the other drivers can't reach at all. The bench fails any trial whose tool input "contains code that runs outside the GUI or touches files", and nothing in the brief or the bench's system prompt tells the agent so. In 17 of the 30 multi-app trials the agent took a side door. In CDB-G04 all ten agents finished the task, and all ten read logs\archive-access.log with FileRead, the log the brief tells them to use, instead of opening it in an app. Five also read the archive site's records.json or the cases store, and one fetched the site's pages with AutoHotkey's Download. In CDB-G03 agents edited the GnuCash book's XML directly, and unzipped and rewrote the Calc workbook through PowerShell, once while Calc still had it open. The bench's own guard caught the PowerShell in five of these trials; score.py's AutoHotkey scan caught all 17. All of CDB-G02's foreground passes stayed in the GUI. After this run, agent.py started adding the GUI-only rule to the bench's system prompt for this bench only; acu/ is unchanged. No trial in this report ran with that prompt.
  2. Background disturbance. All 15 background multi-app trials disturbed the user: the agents activated the Electron apps, Calc or Chrome and used the real pointer and keys. AcuBackground keeps UIA actions behind the user's window, but these apps' trees are sparse enough that the agents fell back to pointer and keyboard input. The other setups also have no background multi-app pass.
  3. CDB-G03 is long. All three foreground trials that stayed in the GUI and missed hit the 45-turn limit before they finished reconciling the workbook.

What changed between the runs

  1. The skill now reaches the agent whole. The first run passed acu/SKILL.md as MCP server instructions, and Claude Code cut them off after "Reuse snippets". The agent never saw the loop, the Act section or the screenshot guidance. That explains the first run's MB-11 misses: three agents started screenshot.ahk with Run, which the GUI-only scan fails. The adapter now installs the skill as a project skill, which is how the bench's Cua Driver arm gets its own.
  2. New helper AcuBackground(target, action) in acu/lib/actions.ahk, with a general "Working behind the user's window" section in the skill. A scripted IR-02 trial showed that UIA .Value := and Invoke() bring a wx window to the front. ControlClick, BM_CLICK and MSAA DoDefaultAction do too, and only ControlSetText doesn't. The helper adds WS_EX_NOACTIVATE to the target's top-level window for the length of the call, as cua-driver's NoActivateGuard does. A desktop regression test covers it (red without the guard, green with it). It doesn't stop an application that calls SetForegroundWindow on itself: the user's window then loses focus to nothing.
  3. Bundled scripts no longer raise dialogs. screenshot.ahk and tree.ahk started by AutoHotkey directly, without the prelude, now print how to run them and exit with code 2. Before, they left modal #Warn and error dialogs on the desktop. The skill now also says to run every script through acu run.
  4. Scorer fixes. FileAppend with no Filename writes no file and no longer counts as a GUI-only hit. That removed two false hits in the BenchLab run. The scan also now flags Download, the file-metadata commands and the HTTP and stream COM objects; that changed no verdict.
  5. Multi-app tasks added. session.py moves their window bounds onto the trial display and keeps the owner's Chrome open (below). run.py now runs all ten v2 tasks by default.

Setup and disclosures

  • Agent: Claude Code 2.1.322, claude -p, Claude Sonnet 5.5, medium effort, 16 000 thinking tokens, 45 turns and 360 s per trial. The only built-in tool was Skill, and the system prompt was the bench's, with "a Windows desktop". Median per trial: 10 turns and 22 s on BenchLab, 26 turns and 90 s on the multi-app tasks.
  • Driver: ACU through bench/cua_driver_bench/acu_mcp.py. Its one tool is run, taking script text or a bundled file and returning screenshots as images. The acu project skill is acu/SKILL.md unmodified after a short note mapping its shell calls onto the tool. The snippet store was empty.
  • Machine: Windows 11 desktop PC. The primary is 3840 x 2160 at 200%, which breaks MB-10 and IR-03 even for the bench's scripted oracle. Trials ran on the secondary, switched to 1920 x 1080 at 100% for each batch and restored afterwards. session.py moved the bench's fixed screen positions there and made the launcher DPI-aware.
  • Multi-app software: LibreOffice 26.8.2, GnuCash 5.17, the owner's Google Chrome, Node 24.14, and Electron 43.8.1 in the four task apps, at the paths the task descriptors name.
  • Validation: the BenchLab oracle passed all seven tasks on the trial display. The multi-app oracle passed CDB-G04 live; for CDB-G02 and G03 it writes the workbook directly and Windows refused the write while Calc had it open, so those two were validated by the bench's own desktop-free tests/test_windows_cdb.py (passed). Do-nothing background trials held all eight criteria on every task, and a deliberate disturbance tripped six.
  • The owner's Chrome: CDB-G04's cleanup stops every chrome.exe in the session by name before and after each trial. session.py narrows that to Chrome processes whose command line names the task workspace, where the trial's --user-data-dir lives. A unit test covers it, and the owner's browser, open since 7 November, stayed open through all 12 G04 sessions. This changes cleanup only, not scoring.
  • Guard exemptions: Cua Spaces.exe (starts PowerShell every 10 s) and svchost.exe (scheduled tasks), via the launcher's own --tool-exe.
  • Reruns: one. The guard stopped foreground CDB-G03 r4 for PowerShell that the owner's herdr SessionStart hook started when another agent session opened on the machine (Windows PowerShell log, event 400). The trial's agent loads no user hooks, and none of its scripts names PowerShell. It was rerun with the same seed; its evidence is in results\acu-sonnet-5-5-v2-invalid\. The first BenchLab run's six kills of the same kind are in results\acu-sonnet-5-5-invalid\.
  • Final-image evidence: none. The bench records state files, event logs and (for the multi-app tasks) the final workspace, not final screenshots, so there are no images to compare.
