What changed between the runs

  1. The trial display is the primary. The superseded 2026-11-12 run used DISPLAY2 as a secondary display. The bench started every task app on the 200% primary and then moved its window over, so Chrome and the Electron apps crossed a DPI change, and LibreOffice and GnuCash, which only use the system DPI, rendered at 200% and were shrunk by half. display.py set --primary now makes DISPLAY2 the primary at 1920 x 1080 and 100% for each batch, through one SetDisplayConfig call, and restore puts the owner's layout back. Apps started after the switch take the new primary's DPI: Calc and GnuCash opened at 96 DPI with no sign-out. session.py no longer has to move the bench's window positions.
  2. The prompt states the GUI-only rule. The 2026-11-11 run left it out, which was a setup error: the bench never states its rule because its own drivers can't leave the GUI, but an ACU script can, and agents in 17 of 30 multi-app trials read or rewrote task files, started PowerShell or fetched URLs.
  3. The skill reaches the agent whole. The first run passed acu/SKILL.md as MCP server instructions, and Claude Code cut them off after "Reuse snippets". The adapter now installs the skill as a project skill, which is how the bench's Cua Driver arm gets its own.
  4. New helper AcuBackground(target, action) in acu/lib/actions.ahk, with a general "Working behind the user's window" section in the skill. It adds WS_EX_NOACTIVATE to the target's top-level window for the length of the call, as cua-driver's NoActivateGuard does. It doesn't stop an application that calls SetForegroundWindow on itself.
  5. Bundled scripts no longer raise dialogs. screenshot.ahk and tree.ahk started by AutoHotkey directly, without the prelude, now print how to run them and exit with code 2.
  6. Scorer fixes. FileAppend with no Filename writes no file and no longer counts as a GUI-only hit. The scan also flags Download, the file-metadata commands and the HTTP and stream COM objects.
  7. Multi-app tasks added. session.py keeps the owner's Chrome open. run.py runs all ten v2 tasks by default. abort.py stops a run at once and restores the machine.

Setup and disclosures

  • Agent: Claude Code 2.1.322, claude -p, Claude Sonnet 5.5, medium effort, 16 000 thinking tokens, 45 turns and 360 s per trial. The only built-in tool was Skill. The system prompt was the bench's, with "a Windows desktop", plus the bench's GUI-only rule: This is a GUI-only run: do the task through the windows of the applications it names. Your scripts may look at and drive windows (screenshots, accessibility trees, keyboard, mouse, clipboard) and print to stdout. A script that starts a program, reads or writes a file or the registry, or fetches a URL fails the task. Median per trial: 10 turns and 20 s on BenchLab, 27.5 turns and 94 s on the multi-app tasks.
  • Driver: ACU through bench/cua_driver_bench/acu_mcp.py. Its one tool is run, taking script text or a bundled file and returning screenshots as images. The acu project skill is acu/SKILL.md unmodified after a short note mapping its shell calls onto the tool. The snippet store was empty.
  • Machine: Windows 11 desktop PC (build 26100). Its 4K monitor at 200% is the usual primary. For each batch the 2560 x 1600 second monitor became the primary at 1920 x 1080 and 100%, and both were restored afterwards. The physical mouse was turned over.
  • Multi-app software: LibreOffice 26.8.2, GnuCash 5.17, the owner's Google Chrome, Node 24.14, and Electron 43.8.1 in the four task apps, at the paths the task descriptors name.
  • Validation: the BenchLab oracle passed all seven tasks on the new primary, and BenchLab's window opened at (40, 40) at 96 DPI. Calc and GnuCash opened at 96 DPI there. The multi-app oracle was validated on the earlier setup (CDB-G04 live; CDB-G02 and G03 through the bench's desktop-free tests/test_windows_cdb.py).
  • The owner's Chrome: CDB-G04's cleanup stops every chrome.exe in the session by name. session.py narrows that to Chrome processes whose command line names the task workspace, where the trial's --user-data-dir lives. The owner's browser stayed open. This changes cleanup only, not scoring.
  • Guard exemptions: Cua Spaces.exe (starts PowerShell every 10 s) and svchost.exe (scheduled tasks), via the launcher's own --tool-exe.
  • Reruns: nine, each with the same seed, all for shells the agent didn't start. Other agent threads ran on the machine during the run: a Codex thread until 03:25 and a "Friction scan" thread with six subagents from 03:26 to 03:31. herdr's SessionStart hooks fired at 03:26:03 and 03:55:12, and a program ran two Get-CimInstance hardware queries at 03:14:12 (Windows PowerShell log, event 400). The guard counts only processes outside the trial's own tree, and score.py's AutoHotkey scan found nothing in any of the nine. Their evidence and a WHY.md are in results\acu-sonnet-5-5-v2-primary-invalid\.
  • Final-image evidence: none. The bench records state files, event logs and (for the multi-app tasks) the final workspace, not final screenshots, so there are no images to compare.
